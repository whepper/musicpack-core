# Psychoacoustic model compatibility contract (Phase 15F)

This document is the written boundary for the scalar psychoacoustic model in
`src/psy/`. It is a faithful, source-derived migration of `codec/libmpcpsy`
(`psy.c`, `psy_tab.c`, `profile.c`, `cvd.c`, `fft_routines.c`, `fft4g.c`,
`ans.c`) and `codec/common/fastmath.c` from the pinned reference build. It is
**not** a clean-room reimplementation.

## 1. Position in the pipeline

```text
PCM (1600 samples/channel)
        │
        ├──────────────► filterbank ──► X ──► SCF / NS / alloc / quant / Huffman
        ▼
  psychoacoustic model  ──► SMR, Transient, MS_Flag, ANSspec
```

The model and the analysis filterbank are **parallel consumers of the same
PCM**; the model does not depend on the filterbank. The model's outputs are the
inputs of the already-verified 15E downstream stages.

## 2. Inputs

* `PcmFrame` — `L`, `R`, `M`, `S`, each at least `ANALYSE_BUFFER = 1600`
  samples. `M = (L+R)*0.5`, `S = (L-R)*0.5`, computed exactly as the reference
  `Read_WAV_Samples` does (the Rust model consumes `M`/`S` from the caller so
  the caller owns that rule).
* Configuration: `quality` (`f32`, `0..=10`) and `sample_rate` (`f32`).

## 3. Outputs consumed by 15E

* `SMR.L/R/M/S` — 32 values each (`SMRTyp`).
* `TransientL/R` — 19 short-partition flags (`PART_SHORT = PART_LONG / 3`).
* `Transient` — 32 FFT-partition flags (`TransientenCalc`).
* `MS_Flag` — 32 flags (`MS_LR_Entscheidung`).
* `ANSspec.L/R/M/S` — 512 FFT-resolution masking thresholds each
  (`MAX_ANS_LINES`), the noise-shaping boundary.

Only bands `0..=Max_Band` are reference-defined for `SMR` and `MS_Flag`; the
Rust model and the tests restrict comparison to that range.

## 4. Per-frame call graph

`Psychoakustisches_Modell` performs two analysis windows over the same frame
(offsets `0` and `576`):

1. CVD (if `CVD_used > 0`): `PowSpec2048` on `L`/`R`, cepstral analysis
   (`CVD2048`), producing voice lines.
2. `PolarSpec1024` → `SubbandEnergy`, `PartitionEnergy`, `CalcUnpred`,
   `WeightedPartitionEnergy`, `SpreadingSignal`, `ApplyTonalityOffset`.
3. `PowSpec256` ×4 → `CalcShortThreshold` (transient detection).
4. `AdaptLtq` (loudness → dynamic threshold offset).
5. `CalcTemporalThreshold` (post-masking) when `tmpMask_used`.
6. Transient short-threshold injection into the simultaneous mask.
7. `PreechoControl`, `ApplyLtq`, `AdaptThresholds`, `CalculateSMR`.
8. M/S branch (`MS_Channelmode > 0`): `PowSpec1024` on `M`/`S`,
   `CalcMSThreshold`, `ApplyLtq`, `AdaptThresholds`, `CalculateSMR`.
9. `ANSspec` accumulation (`min` across the two windows).

Then, at the encoder level: `RaiseSMR` (if `minSMR > 0`),
`MS_LR_Entscheidung` (if `MS_Channelmode > 0`), `TransientenCalc`.

## 5. State

All state is per-instance in `PsychoacousticModel`; there is no global mutable
state and independent instances are isolated.

| State | Initial value | Lifetime |
|---|---|---|
| `a,b,c,d` (masking integrators) | 0 | cross-frame |
| `T_L/R` (post-mask time constants) | 0 | cross-frame |
| `Xsave_L/R`, `Ysave_L/R` (amp/phase history, 3×512) | 0 | cross-frame |
| `pre_erg_L/R` (short-partition history) | `INIT_PART_LTQ` | cross-frame |
| `PreThr_L/R` (pre-echo thresholds) | `INIT_PART_LTQ` | cross-frame |
| `tmp_Mask_L/R` (post-mask thresholds) | `INIT_PART_LTQ` | cross-frame |
| `loud` | 0 | cross-frame |
| `Vocal_L/R` | 0 | per frame |
| `ANSspec_L/R/M/S` | 0 | per frame |
| `ip` (FFT bit-reversal) | `ip[0]=ip[1]=512` | per instance |

`INIT_PART_LTQ` is the degenerate seed the reference computes while
`SampleFreq == 0` and the ear model is zeroed: `(float)pow(10, -2.3)`, frozen
as `0x3BA43AA2`. This matters because the reference calls
`Init_Psychoakustik` (with `SampleFreq = 0`) **before** the real sample rate is
known, and only re-runs `Init_Psychoakustiktabellen` afterwards — the
pre-echo/post-mask state keeps the degenerate seed.

## 6. Tables

Literal source data (transcribed, not generated):

* partition geometry `wl`, `wh`, `iw`, `wl_short`, `wh_short`, `iw_short`
  (`psy_tab.c`);
* `Puls[9]`, `CosWin[256]` (`cvd.c`), frozen as bit patterns;
* profile table `Profiles[16]` (`profile.c`).

Libm-derived tables are **frozen as IEEE-754 bit patterns** in
`src/psy/frozen.rs`, generated by `tools/extract_psy_oracle.c` and transcribed
by `tools/gen_psy_tables.py`:

* `SPRD` (57×57 spreading), `MinVal`, `Loudness`, `partLtq`, `invLtq`,
  `fftLtq`, `O_MAX`/`O_MIN`/`FAC1`/`FAC2` — per frozen configuration;
* `w` (FFT twiddles), `Hann_256/1024/1600`, `tabcos`, `tabatan2` — rate
  independent.

They are frozen because they depend on the host math library; regenerating them
with a different libm would change the output.

## 7. Numerical contract

The reference build defines `FAST_MATH` and `CVD_FASTLOG`. On the pinned
Apple/arm64 toolchain:

* `POW`, `POW10`, `LOG10`, `SQRT` are the **double** libm functions cast back
  to `float` (`mpcmath.h`);
* `COSF`/`ATAN2F` are the table-driven `my_cos`/`my_atan2`;
* `IFLOORF` is the bit-trick `my_ifloor`;
* `logfast` is the `CVD_FASTLOG` bit-manipulation log.

The crate reproduces each exactly:

* `pow10` must call the generic `pow`, not LLVM's `exp10` special case for a
  literal base ten, so the base is passed through `black_box`; generic `pow`,
  `log10`, `sqrt`, `cos`, `sin`, `atan`, `asinh` match Apple libm bit-for-bit
  (verified in `psy::math`).
* `f32` arithmetic stays `f32`; double literals (`0.98`, `0.02`, `0.5`, `4.`,
  `0.025`, `1.e18`, …) and libm calls keep their `f64` precision and narrowing
  points.
* `CVD_UNPRED * 0.01 * vocal` is evaluated in `f64` and narrowed once, exactly
  as the reference does.
* `my_atan2`/`my_cos`/`my_ifloor`/`lrintf` are bit-exact ports.

## 8. FFT boundary

* Forward-only real FFT (`rdft`) from `fft4g.c`, driven by the frozen `w`
  table; the bit-reversal table `ip` is recomputed per call and kept per
  instance.
* Windowed kernels: `PowSpec256` (`Hann_256`), `PowSpec1024`/`PolarSpec1024`
  (`Hann_1024`), `PowSpec2048` (`Hann_1600` centred in 2048),
  `Cepstrum2048` (mirror + FFT + `0.9888/2048` scaling).
* `ATAN2F` (phase) is the table-driven `my_atan2`.

## 9. CVD boundary

`CVD2048` (`CVD_used` 1 or 2) log-windows the lower 512 power lines with
`logfast`, runs `Cepstrum2048`, and runs `CEP_Analyse2048` (one search for
`CVD_used == 1`, a second upsampled search for `CVD_used >= 2`). Detected
harmonics cap `cw` in `CalcUnpred`.

## 10. Quality / profile and sample rate

`SetQualityParams` maps `quality` through `Profiles[16]`
(`i = (int)quality + 5`, linear interpolation for fractional quality). q4–q7
are Radio/Standard/Xtreme/Insane; `MS_Channelmode` is 6/11/12/13. The model is
called with `MaxBand = 31` regardless of bandwidth; the bandwidth-derived
`Max_Band` (used by `RaiseSMR` and downstream allocation) is
`clamp(BandWidth * 64 / SampleFreq, 1, 31)`.

Frozen tables cover the complete **integer SV8 quality surface**: quality
`0..=10` (exact integer values) at 44100, 48000, 37800 and 32000 Hz — 44
configurations, transcribed from the C oracle dumps
`tests/data/psy/psy_<q>-<rate>.txt` by `tools/gen_psy_tables.py`.
`frozen_psy_tables` matches the pair by exact `f32` bit equality; any other
pair returns `None` and `PsychoacousticModel::new` fails with
`EncoderError::UnsupportedPsyConfig` (no fallback, no remapping).

**Fractional parity (J.2): complete.** The C encoder accepts a continuous
`--quality` value clipped to `[0, 10]` and interpolates adjacent profile
rows; the Rust path reproduces this for **any finite `f32` quality** at the
four SV8 rates:

* integer pairs keep resolving to their frozen C-oracle tables by exact
  `f32` bit equality (permanent regression oracles — no quantization, no
  rounding, no fractional lookup grid);
* every other finite quality is computed deterministically by
  `psy::computed`: the existing profile interpolation
  (`PsyParams::from_quality`, including the `[0, 10]` clip), the existing
  `math::{pow10_d, mind, minf}`, the quality-independent per-rate
  `Loudness`/`SPRD`, and the frozen ATH base arrays (`psy_bases.txt`:
 4 rates ×10 `EarModelFlag`s ×512 `f64` words, captured after the flag
  roll-off and before the `Ltq_max` clamp). The extractor's `selfcheck`
  mode proves the written bases reconstruct the reference `fftLtq` /
  `partLtq` / `invLtq` for44 integer +23 fractional configs (`67/67`), and
  `psy::computed`'s tests prove `computed tables == frozen tables` for all44
  integers plus the23 committed fractional C-oracle dumps;
* **non-finite qualities (`NaN`, `±inf`) are rejected** with
  `EncoderError::NonFiniteQuality` — an intentional compatibility boundary:
  C's `NaN` path is undefined/platform-dependent, so no parity is claimed;
* no codec semantics changed: same four rates, same channels, same `EI`
  interpretation (`(quality+5)*8` rounding), and the Author product UI
  remains integer-only (q5/6/7/8).

## 11. Source-derived vs frozen vs Rust decisions

* **Source-derived:** all model logic, constants, profile table, partition
  geometry, `Puls`/`CosWin`.
* **Frozen:** libm-derived numerical tables, FFT windows/twiddles, `tabcos`/
  `tabatan2`, the degenerate state seed, and the J.2 ATH base arrays
  (`psy_bases.txt` → `frozen.rs`).
* **Rust decisions:** explicit per-instance state, `Result`-based configuration
  errors, no globals. None of these change reference-observable values.

## 12. Explicit non-goals

No SIMD, no optimisation, no production integration, no C-encoder removal, no
FFI/unsafe. Those are later phases.
