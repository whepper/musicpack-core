# Whole-encoder oracle (Phase 15G)

Committed `.mpc` streams produced by the reference `mpcenc` binary from
deterministic integer-only 16-bit stereo WAVs, plus the manifest the Rust
whole-encoder test replays. The Rust test never invokes C.

## Provenance

* reference `mpcenc` `build/codec/mpcenc/mpcenc` (revision `05d97a5`,
  `musicpack` HEAD `d687b645760c68cca2d1cb36ab586db0092ff0b3`);
* Apple clang 21, arm64, `-O0`, `-ffp-contract=off`, `FAST_MATH` +
  `CVD_FASTLOG`, `MPC_ENABLE_ENC_SIMD_KERNEL`;
* scalar-forced via `--impl scalar --psy-impl scalar` (the strict
  compatibility target; verified byte-identical to the committed fixtures
  for all 21 cases in Phase 15G.2, so no regeneration was needed);
* generated by `tools/gen_encoder_fixtures.py <mpcenc> <reference-repo>`.

The PCM generator is integer-only (LCG noise, ramp, alternating, constant,
impulse, transient) so the Python and Rust generators are bit-identical
without floating point.

## Integer-parity matrix corpus (J.1)

`matrix_manifest.txt` records the extended corpus (`name quality rate kind
frames channels bytes sha256`):

| Rows | Coverage |
|---|---|
| 88 | `noise` (5000 frames) and `transient` (25000 frames) for **every** integer quality `0..=10` × every SV8 rate — 44 configurations × 2 signals |
| 4 | mono `noise` at `q5` × 44100/48000/37800/32000 Hz |
| 5 | long multi-`AP`-block `noise` (93728 frames): `q0-44100`, `q10-44100`, `q5-48000`, `q5-37800`, `q5-32000` |

Rows whose names collide with the original 21-case corpus reuse those frozen
files unchanged. All rows are generated by the same tool/binary/flags as the
original corpus (scalar-forced `mpcenc` 1.32.0 from the pinned reference
environment); `tests/encoder_matrix.rs` reproduces every row byte-for-byte
and validates each stream structurally as SV8 (framing, `SH` CRC/fields,
`EI` profile/PNS/version, `SO`/`ST`/`SE`). The generator never rewrites an
existing `.mpc` file — re-running it only adds missing fixtures.

Phase 15G.1 resolved the two remaining divergences (`q5-44100-oneframe`,
`q5-44100-multiblock`, both in decoder-delay/padded frames). Root cause: the
frozen CVD tables `PULS`/`COS_WIN` (`src/psy/cvd_tables.rs`) were byte-swapped
by the table generator (`struct.pack("<f", v).hex()` misread as a hex
integer), so `CosWin[0] = 1.0` became a denormal ~4.6e-41, the cepstral window
collapsed, and voice was never detected. Scalar-forced C output was verified
byte-identical to the committed SIMD fixtures on both cases, proving the
divergence was a genuine table bug rather than scalar-vs-SIMD drift. See the
Phase 15G.1 report and the `frozen_cvd_tables_match_reference_constants` /
`harmonic_spectrum_detects_voice_like_reference` regression tests in
`src/psy/cvd.rs`.

## Wide-PCM corpus (J.6)

`wide_manifest.txt` records the J.6 wide-PCM corpus (`name quality rate kind
depth frames channels bytes sha256`), generated by the same tool/binary/flags
as every earlier corpus (scalar-forced `mpcenc` 1.32.0, additive — existing
fixtures are never rewritten):

| Rows | Coverage |
|---|---|
| 4 | 24-bit `noise` at q5 × every SV8 rate |
| 3 | 24-bit deterministic `ramp` / `lowamp` / `fullrange` at q5/44100 |
| 1 | mono 24-bit `noise` (the C mono conversion branch) |
| 3 | 32-bit deterministic `ramp` / `lowamp` / `fullrange` at q5/44100 |

Signals are integer-only so the Python and Rust generators are bit-identical:
`ramp` is an odd-step sawtooth spanning almost the full scale of the depth;
`lowamp` is LCG noise confined **below the 16-bit truncation threshold**
(`s24 ∈ [0,255]` / `s32 ∈ [0,65535]`, invisible to `>> 16`); `fullrange`
starts with the exact minimum/maximum then runs full-range LCG noise; `noise`
is full-range LCG noise. The WAVs are kept in `/tmp/mpj6-wav/` by the
generator as input to the conversion-oracle tool below.

`tests/encoder_wide.rs` replays every row through
`MusepackEncoder::encode_s32` byte-for-byte (first-divergence diagnostics)
and additionally proves each wide row **differs** from the stream its `>> 16`
`i16` truncation would encode.

## PCM conversion oracle (J.6)

`pcm_conversion_oracle.txt` (1800 rows over three sections: 24-bit stereo,
32-bit stereo, 24-bit mono) records the *intermediate* reference conversion
values from `Read_WAV_Samples`: the left-aligned `i32` inputs, the pre-fix
`f24`/`f32` values, and the stored `L`/`R`/`M`/`S` `f32` bit patterns — all
produced by `tools/extract_pcm_oracle.c` (temporary migration tooling: not
built by Cargo, never invoked by Rust tests). The unit test
`read_block_matches_the_c_pcm_conversion_oracle` replays the recorded inputs
through the Rust input path and requires bit-equal pre-fix values and
analysis buffers, so a passing stream differential cannot conceal a
conversion coincidence.

## Diagnostics

`tools/extract_encoder_trace.c` replays the exact `mpcenc.c` frame loop
(including decoder-delay frames) with scalar kernels forced and dumps a
per-frame trace (`Res`, `SCF`, `MS`, `Q`, `X`, `SMR`, FFT power/phase,
unpredictability, transient flags, CVD voice lines, psy state). It is temporary
migration tooling: not built by Cargo, never invoked by Rust tests.

The Rust side exposes the same boundaries through
`MusepackEncoder::encode_traced` (`FrameTrace`).
