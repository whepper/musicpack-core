# Frozen encoder compatibility fixtures

This directory holds the **frozen compatibility artifact** for the Rust
Musepack encoder: the expected whole-file SHA-256 of the reference encoder's
output for every input in the deterministic encoder corpus.

## `encoder_reference_manifest.txt`

A byte-for-byte mirror of the reference repository's canonical Phase 2
manifest. It must **never** be regenerated, edited or re-frozen to accommodate
a Rust encoder result. `tests/reference_manifest.rs` pins both its structure
(94 inputs × q5/q6/q7 = 282 vectors) and its exact bytes.

| Field | Value |
|---|---|
| Source repository | `https://github.com/whepper/musicpack` |
| Source path | `tests/encoder_reference_manifest.txt` |
| Source commit | `d687b645760c68cca2d1cb36ab586db0092ff0b3` |
| SHA-256 (source and mirror) | `2f628c79efedd6062d2ae86373d8ebfc78230c330cb7f58d643dbb1acd215bc9` |
| Vectors | 282 (94 inputs × quality 5, 6, 7) |
| Inputs | generated by `tests/generate_encoder_corpus.py` (not committed; deterministic) |

## Reference environment the manifest is valid for

The manifest encodes whole-file hashes, which include the SV8 `EI` (encoder
info) block. It is therefore only reproducible under the pinned reference
build described in the manifest header:

* pristine reference encoder r475 / git `05d97a5`, patched to report version
  `1.32.0` (`tests/patch_reference.py`);
* Apple clang 21, arm64, **`-O0`** (no optimization);
* `-ffp-contract=off` (FMA contraction disabled; `/fp:precise` on MSVC);
* `FAST_MATH` + `CVD_FASTLOG` enabled.

The reference encoder is **not** cross-platform byte-identical: floating-point
codegen and the libm-derived initialization tables differ between toolchains
(for example, x86-64 gcc `-O0` does not match this manifest). CI therefore
compares against a live reference binary built by the same toolchain rather
than this manifest. See `crates/musicpack-musepack-encoder/README.md`.

## Why the mirror lives here

The legacy C encoder is a temporary oracle and will be deleted. Freezing the
manifest in the crate that owns the Rust encoder keeps the compatibility
boundary available after that deletion. The input WAVs are **not** copied —
they are generated deterministically and are not duplicated here.

## `container-*.txt` — SV8 container fixtures (Phase 15C)

Seven compact textual fixtures extracted from reference `.mpc` output with
`make_container_fixtures.py` (a pure standard-library SV8 parser; it never
invokes the C encoder). They capture each block's key, encoded size field, CRC
(where present) and payload bytes, plus the seek-table parameters and the
`SO` placeholder offset. `AP` payloads are recorded only as a length and
SHA-256, so the fixtures stay small.

| Fixture | Covers |
|---|---|
| `container-sine32-q8.txt` | 32000 Hz `SH`; single `AP`; CRC `SH` |
| `container-sine37-q4.txt` | 37800 Hz `SH` |
| `container-sine44-q5.txt` | 44100 Hz `SH`; no-CRC blocks |
| `container-sine48-q6.txt` | 48000 Hz `SH` |
| `container-sine44-q5-48s.txt` | long stream, 29 `AP` blocks, seek table with 15 entries |
| `container-sine44-q5-48s-seek0.txt` | `--seek_distance 0`, one seek entry per `AP` block, Golomb deltas |
| `container-sine44-q5-frames1.txt` | `--num_frames 1`, small `AP` blocks, multi-byte size fields |

They are frozen. `tests/container_fixtures.rs` verifies the Rust writers
against them (block bytes, `SH`/`EI`/`RG`/`SO`/`ST` payloads, the `SO` patch,
and the size fields), and the tests require **no C encoder**. Regenerating them
to accommodate a Rust result would defeat the compatibility contract; add a
deliberate new case instead, and record why.

## `filterbank/` — analysis-filterbank oracle (Phase 15D)

Frozen bit-exact outputs from the C analysis filterbank (`Analyse_Init` /
`Analyse_Filter`) over deterministic PCM `f32` inputs, plus the post-`Klemm`
`Ci_opt` and `M` bit dumps. See `filterbank/README.md` for the representation,
the case list, the reference environment and the (temporary) extraction tool.
`tests/filterbank_fixtures.rs` consumes them and requires **no C encoder**.
