# G-6B instrument-check run provenance

A record of one execution of the corrected instrument. This file is written by
hand at authoring time and is deliberately NOT regenerated by `g6b`, because it
records the identity of one run rather than a property of the code.
`REPORT.txt` is the regenerating, byte-deterministic artefact and is what the
tests compare against.

## What this artefact is — and is not

- **Is:** an instrument check. It exists to demonstrate that the corrected
  measurement measures what it claims: its mixed column reproduces the
  historical `fixtures/g6/REPORT.txt` headline numbers exactly, and its
  symmetric column shows the documented correction (§4.1 of
  `G6B_METHODOLOGY.md`).
- **Is not:** criteria evidence. The acceptance criteria in
  `G6B_METHODOLOGY.md` §11 were frozen before this artefact was generated, and
  the same-data prohibition (§14 rule 3) forbids evaluating them against the
  surrogate that motivated the G-6A repair. No verdict may cite this file.

## What was run

- command: `cargo run --manifest-path experiments/music-similarity-eval/Cargo.toml --bin g6b -- --out experiments/music-similarity-eval/fixtures/g6b`
- toolchain: `rustc 1.97.1 (8bab26f4f 2026-07-14)`
- experiment crate version: 0.1.0
- date of record: 2026-09-27 (regenerated after the readiness implementation;
  see `G6B_IMPLEMENTATION.md` and `G6B_METHODOLOGY.md` §18)
- network access: none. No model download, no audio, no CLAP, no inference, no
  database, no music library. Every input is generated deterministically in
  `src/g6b.rs` from the unchanged `g6` surrogate corpora (SHA-256 counter-mode
  stream).
- two consecutive runs produced the identical report digest
  `c67e0992381813d0a3c2d3523f306003059a0122b8b3ab12c803ee184ef9468b`.

## What the instrument now also measures

Beyond the original symmetric/mixed pairwise columns, the instrument-check
report carries:

- the B-C profile measurements (per-vector norm conformance, subnormal energy
  fraction, storage-path rejection count) — as **measurements only**;
- album-level retrieval at the ADR-sketched k = 12, with both worlds'
  aggregates recomputed independently from that world's own stored vectors
  (`G6B_METHODOLOGY.md` §18 R-3);
- the full unconditional reversal census, now including album-level events.

The frozen seven-gate evaluation (`g6b::evaluate_gates` / `run_corpus_experiment`)
is deliberately **not** invoked anywhere in this artefact: the same-data
prohibition (§14 rule 3) confines gate evaluation to the real corpus. Gate
machinery tests run on small hand-built synthetic corpora, never on the
surrogate.

## Representations compared

- reference: the canonical f32 vector as the producing pipeline delivers it —
  L2-normalized (`eval::pool_mean_norm` semantics).
- stored: `f16_bits_to_f32(f32_to_f16_bits(v))`, component-wise, **for both
  operands of every pairwise score and for the query in every ranking**. This
  is the storage path of `G6B_METHODOLOGY.md` §4: the query is itself a stored
  track vector (ADR 0017 §5.8), so it travels the same path as the candidates.
- the historical mixed regime (only the second operand quantized) is measured
  alongside and reported in the `mixed_max_abs_delta_cosine` lines, so the
  correction is visible rather than silent.
- no renormalization after the round trip; `eval::cosine` divides by both
  norms; the norm perturbation is measured and reported.

## Procedures reused unchanged

| Step | Function | Note |
| --- | --- | --- |
| cosine | `eval::cosine` | f64 accumulation over f32 inputs, returns f32 |
| ranking | `eval::nearest` | self excluded, score descending with `total_cmp`, index tie-break, truncated |
| album aggregate | `eval::aggregate_albums` | mean over members then L2 |
| surrogate corpus | `g6::Corpus::surrogate` | parameters unchanged (spread 0.35, cluster_spread 0.55) |
| binary16 conversion | `docfmt::f32_to_f16_bits` / `f16_bits_to_f32` | FORMAT_SPEC §7.4, RNE ties-to-even |

No reimplementation of any of these. `src/g6.rs` is untouched: the historical
G-6 instrument and its committed artefact remain pinned to each other.

## Vector source identity

- source: **deterministic surrogate corpus**, generated in `g6::Corpus`,
  parameters identical to the G-6 run: 45 tracks, 15 clusters of 3, at 1280
  (`primary`), 512 (`secondary`) and 16 (`tiny`) dimensions.
- the recorded Discogs-EffNet run outputs are not in this repository (`*.json`
  is gitignored; the model is never downloaded here). The real-corpus
  requirements are `G6B_METHODOLOGY.md` §13.

## Determinism

`REPORT.txt` contains no timestamp, no path, no host name and no toolchain
string, precisely so that two runs are byte-comparable. Enforced by
`g6b_tests::the_report_is_byte_identical_across_independent_runs` and
`g6b_tests::the_committed_report_matches_the_current_code`.

## Privacy

No username, no absolute user-home or filesystem path, no music-library path,
no artist, album or track name, and no secret appears in `REPORT.txt` or in
this file. Track identities are anonymous and positional (`t00`…`t44`, clusters
`c00`…`c14`). Enforced by
`g6b_tests::no_result_artefact_leaks_a_path_a_username_or_metadata` and
`g6b_tests::the_experiment_claims_nothing_about_perceptual_quality`.

## Order of operations (the freeze discipline)

1. `G6B_METHODOLOGY.md` written, with the §11 criteria frozen — no surrogate
   number appears in §11 or §12.
2. This instrument check generated and committed afterwards.
3. The eventual real-corpus run executes §13 under §14's rules; its artefacts
   will live outside this surrogate fixture set and will carry the corpus
   provenance §13 requires.
