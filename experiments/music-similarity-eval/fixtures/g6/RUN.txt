# G-6 run provenance

A record of one execution of the experiment. This file is written by hand at
authoring time and is deliberately NOT regenerated by `g6`, because it records
the identity of one run rather than a property of the code. `REPORT.txt` is the
regenerating, byte-deterministic artefact and is what the tests compare against.

## What was run

- command: `cargo run --manifest-path experiments/music-similarity-eval/Cargo.toml --bin g6 -- --out experiments/music-similarity-eval/fixtures/g6`
- toolchain: `rustc 1.97.1 (8bab26f4f 2026-07-14)`
- experiment crate version: 0.1.0
- date of record: 2026-09-26
- network access: none. No model download, no audio, no CLAP, no inference, no
  database, no music library. Every input is generated deterministically in
  `src/g6.rs` from a SHA-256 counter-mode stream.

## Representations compared

- reference: the canonical f32 vector as the producing pipeline delivers it —
  L2-normalized, `eval::pool_mean_norm` semantics (per-window L2, mean, track L2).
- candidate: `f16_bits_to_f32(f32_to_f16_bits(v))`, component-wise.
- conversion: the already-specified binary16 rules of FORMAT_SPEC §7.4 —
  round to nearest, ties to even; subnormals produced and supported; an input
  that would round to infinity is rejected; ±0 from underflow is a real value.
  Implemented by `docfmt::f32_to_f16_bits` / `docfmt::f16_bits_to_f32`, which
  are the same functions the format's fixtures pin.
- no renormalization after the round trip. The producing pipeline normalizes
  before storage and `eval::cosine` divides by both norms, so the comparison is
  already normalization-robust. Renormalizing would hide the norm perturbation
  that is one of the things under test. The perturbation is measured instead and
  reported as `candidate_norm_range` / `max_norm_deviation`.

## Procedures reused unchanged

| Step | Function | Note |
| --- | --- | --- |
| cosine | `eval::cosine` | f64 accumulation over f32 inputs, returns f32 |
| ranking | `eval::nearest` | self excluded, score descending with `total_cmp`, index tie-break, truncated |
| album aggregate | `eval::aggregate_albums` | mean over members then L2 |

No reimplementation of any of these. The Spearman coefficient is new (it is not
part of the existing pipeline) and is implemented in `g6::spearman` with average
ranks for ties, checked against known inputs in `g6_tests`.

## Vector source identity

- source: **deterministic surrogate corpus**, generated in `g6::Corpus`.
- reason: the recorded Discogs-EffNet run outputs are not in this repository
  (`*.json` is gitignored, the model is never downloaded here), so the recorded
  corpus could not be read. Recorded as a scope limitation in G6_F16.md §3
  *before* the experiment was run.
- shape: 45 tracks, 15 clusters of 3, matching the recorded run.
- dimensions evaluated: 1280 (primary, Discogs-EffNet `multi`), 512
  (secondary), 16 (dimension-sensitivity probe).
- construction: 15 unit cluster centres pulled toward one another by
  `cluster_spread = 0.55`, then per-track `normalize(centre + noise · spread)`
  with `spread = 0.35` and a per-member noise scale, so within-cluster cosines
  spread out instead of being identical.
- values: SHA-256 counter-mode stream, so the corpus is byte-reproducible on any
  platform with no floating-point behaviour in the generator.
- supplementary only, not part of the verdict: the same construction with
  `spread = 0.02`, which makes within-cluster neighbours near-tied on purpose.

## Profile identity

No profile was created, and none is claimed. The experiment measures the
*encoding* against a synthetic vector population; it does not analyse audio and
does not produce a `profile_fingerprint`. The two synthetic fixture profiles that
exist for the format fixtures are unrelated to this experiment and are not used
here.

If a future run repeats this against a recorded corpus, the record must include
the `profile_fingerprint`, the model variant, the patch hop and the corpus
identity digest, so that the two runs are comparable.

## Criteria evaluated

The ten criteria predeclared in G6_F16.md §2: C1…C6 taken verbatim from
FORMAT_SPEC §7.3, C7…C10 added there before the run. Thresholds are not restated
here; G6_F16.md is the single source, so a threshold cannot drift between the two
documents.

## Determinism

`REPORT.txt` contains no timestamp, no path, no host name and no toolchain
string, precisely so that two runs are byte-comparable. Verified by running the
generator twice and comparing SHA-256, and enforced by
`g6_tests::the_report_is_byte_identical_across_independent_runs` and
`g6_tests::the_committed_report_matches_the_current_code`.

## Privacy

No username, no absolute user-home or filesystem path, no music-library path,
no artist, album or track name, and no secret appears in `REPORT.txt` or in this
file. Track identities are anonymous and positional (`t00`…`t44`, clusters
`c00`…`c14`). The detector matches *paths* rather than bare substrings, so this
file may name the patterns it excludes. Enforced by
`g6_tests::no_result_artefact_leaks_a_path_a_username_or_metadata`.
